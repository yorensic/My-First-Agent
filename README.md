# 最小 Agent 实现作业

## 一、Agent Loop 是怎么转起来的？
本项目通过双层 while True 循环实现 Agent 核心机制：

1. 用户输入内容，外层循环接收输入并存入 messages 历史记录。
2. 内层循环携带历史记录（messages）和工具清单（tools）请求大模型（DeepSeek）。
3. 若模型返回普通文本，直接打印并跳出内层循环。
4. 若模型返回 tool_calls（工具调用请求），则解析参数，通过 TOOL_MAP 找到本地函数执行（如 run_bash）。
5. 将执行结果（完整内容）封装为 role: tool 的消息回填至 messages 中。
6. 内层循环再次请求大模型，直到它不再调用工具，输出最终结论。

## 二、我踩的三个坑
1. **环境变量配置坑**：一开始没配系统环境变量，后来学会了用 sysdm.cpl 新建 DEEPSEEK_API_KEY，并踩了“配完必须重启 cmd 才能生效”的坑。
2. **文件格式坑**：一开始代码存成了 txt 格式，运行报错。后来学会在记事本另存为时，必须选“所有文件 (*.*)”和“UTF-8”编码。
3. **思考模式关闭坑**：请求 DeepSeek 时如果没有加 `extra_body={"thinking": {"type": "disabled"}}`，大模型有时会陷入长时间的内部思考导致响应极慢。

## 三、安全防护（选做）
在 run_bash 函数中，我利用 re 库编写了 DANGER_PATTERNS 黑名单，用正则表达式拦截了诸如 rm -rf、shutdown 等危险系统命令，在工具执行前做了一层安全防护。
